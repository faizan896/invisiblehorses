From request to receipt

Autonomy, with boundaries.

One place to manage what your agents can spend and when a human needs to step in.

01 / Access

Give each agent its own key.

Choose payment or read permissions. Revoke a key when its job is done. An agent cannot approve its own requests.

02 / Control

Set the budget before the task.

Limit each payment, cap daily spending and choose allowed vendors. Pending requests reserve budget too.

03 / Follow through

Close the tab. Work continues.

Accepted requests run in a durable background worker. Retrying the same request does not create a second payment.

Finance and operations

These are intended use cases. Vendor purchases and external payouts need a connected payment provider. The public demo does not make those purchases.
