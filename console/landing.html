02 / The system

Permission before execution.

The company pilot keeps provider credentials on the backend. An agent can request work; it cannot change spending rules or approve its own request.

  1. 01Agent request

    A scoped key and an assigned customer job.

  2. 02Budget check

    Reserve the quoted cost within the current limits.

  3. 03Owner decision

    When the approval threshold is exceeded.

  4. 04Provider execution

    Send the authorized input with a stable request key.

  5. 05Status and receipt

    Match the provider outcome before confirming.

An uncertain outcome retains its budget reservation. Retrying a request does not create a replacement charge.

A provider status response records what the supplier reports. It is not proof of bank, card or blockchain settlement.

03 / Use and scope

For teams building paid agent tools.

A research agent buying data is one intended use case. The company sets budgets per customer job and keeps control of the supplier account.
